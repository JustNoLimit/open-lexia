1 · Session

listList the 23 known ECUs with their CAN addresses.
connect <ECU>Open a diagnostic session. Takes the family name, not a label — connect BMF (BSI), connect INJ (engine), connect ABRASR (ABS/ESP).
exitClose the session. Also disconnect.
statusShow what is connected, unlocked and whether write mode is on.
identRead the ECU identification block (VIN, part number, supplier, software version).
scanGlobal Test: try every ECU in turn and report which answer and which have faults.
pdiPre-Delivery Inspection — a full scan plus a printed report.

2 · Write protection and security

rw on / rw offLeave or re-enter read-only mode. The firmware — not the UI — blocks write, clear, trace, actuator, flash, service, program, esp and raw until this is on.
pin <hex>Set the 16-bit SecurityAccess PIN for the connected ECU, e.g. pin B2B2. Needed when the built-in family default is wrong or unknown — look yours up in docs/ECU_KEYS.md.
unlockRun seed/key against the ECU. Required before any configuration write.

3 · Faults

dtcRead stored fault codes and decode them to P/C/B/U text.
clearClear stored faults on the connected ECU. Needs rw on.

4 · Reading and writing data

read <zone>Read one zone/identifier as raw hex. Bare hex, no 0x: read F190. Values above FF are sent as UDS 22 xxxx, below as KWP 21 xx.
write <zone> <hex…>Write a zone, e.g. write F190 12 34. Needs unlock and rw on. Prefer the Telecoding tab — it does read-modify-write on single bits instead of overwriting the whole zone.
config listList every known BSI configuration parameter.
config read <zone>Read one configuration zone and decode its parameters.
config readallRead every configuration zone in sequence.
traceWrite traceability data (UDS 2901 / KWP A0). Needs rw on.

5 · Live measurements

meas <id>Add a parameter to the live poll, e.g. meas 100A. Several can run at once.
meas offStop all measurement polling.
live <id> / live offSame idea for a single parameter.
obd <pid> / obd offStandard OBD-II Mode 01, no session needed: obd 0C = RPM, obd 0D = speed, obd 05 = coolant. These are generic and verified, unlike most PSA identifiers.

6 · Discovery — finding unknown identifiers

PSA never published the measurement identifiers Lexia 3 uses, so they have to be found on the car. These commands are how.

lidscanAsk the connected ECU for every identifier from 00 to FF and report which answer. Read-only, works without rw on.
lidscan <a> <b>Sweep a specific range, e.g. lidscan 0100 01FF for UDS DIDs.
lidscan stopAbort a running sweep.
Identifiers reported as present, refused exist but need unlock first — run the sweep again after unlocking.
sniff rawRaw CAN monitor: print every frame as hex, sampled to a few lines per second so the link is not flooded.
sniff on / sniff offDecoded-only monitor (about 50 known identifiers) / stop monitoring.
gsniff rate hs / lsSwitch the MCP2515 between 500k (HS) and 125k (LS) and put it in listen-only mode. The Sniffer tab buttons do this for you.
gsniff watch hs <id>Follow one identifier continuously, unsampled — e.g. gsniff watch ls 1D0 for the climate frame.
gsniffPrint the rest of the guided-sniffer subcommands (baseline, count/hold/sweep capture, report, save/load).
raw <hex…>Send a hand-built PDU, e.g. raw 21 80. Needs rw on, since it can encode any service including writes.

7 · Actuators and procedures

The routine identifiers behind these are not verified against a source. On the wrong ECU an unknown routine can act on real hardware. Treat everything in this section as experimental.

actuator <id> [args]Start an actuator routine on the connected ECU, e.g. actuator 3101.
service resetReset the maintenance indicator (BSI).
service schedule <km> <months>Set the maintenance interval.
esp calibSteering angle sensor calibration. Vehicle level, wheels straight.
esp bleedABS hydraulic bleeding. Keep the reservoir full throughout.
program keyEnter key learning mode.
program initDangerous. BSI factory initialisation — resets configuration, keys and radio code.

8 · Firmware download

flash <S-record>Stage one S1/S2/S3 line. Stage the whole image before flash begin.
flash beginOpen the programming session, erase, and start the transfer.
flash endFinish: transfer exit plus checksum verification.
flash status / flash cancelShow the state machine step / abort and drop the staged records.

9 · Hardware

hwtestSelf-test: SPI register readback plus a CAN loopback on the MCP2515. Run this first if nothing responds.
helpPrint the device's own command list into the console.

Typical order of work

  1. hwtest — confirm the CAN controller is wired and alive.
  2. scan — see which ECUs answer.
  3. connect BMF → dtc — read faults.
  4. unlock (with pin if the default fails) before anything that writes.
  5. rw on — only once you intend to change something.
  6. lidscan — to discover parameters that are not in the database yet.
